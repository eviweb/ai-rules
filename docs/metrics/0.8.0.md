## Scoped rules (on demand)

Measured in one session (2026-11-24, `claude-opus-5-5`, `/context all` after each read). A matching `Read` injects the rules as a system reminder attached to the result, so `/context` counts them under **Messages**, not Memory files. Each rule is paid once per session.

| File read | File bytes | Rules loaded | Rule bytes | ~Tokens | Rule bytes / file bytes |
|-----------|------------|--------------|------------|---------|-------------------------|
| `scripts/measure-context.sh` | 6,846 | 6 (`shell`, `cli`, `naming`, `error-handling`, `logging`, `compatibility`) | 17,386 | ~6.4k | 2.5 |
| `.github/workflows/ci.yml` | 2,798 | 1 (`ci`) | 6,041 | ~2.2k | 2.2 |
| `CHANGELOG.md` | 23,870 | 4 (`docs`, `release`, `changelog`, `versioning`) | 9,086 | ~3.4k | 0.4 |

Cumulative: 11 files, 32.5 KB, about 12k tokens, 3.4 times the always-on core.

Two triggers were too broad and are narrowed after this measurement (`tests/test_scoped_rules_triggering.py` pins the result):

- `logging` (application-level) and `compatibility` no longer match `**/*.sh`; `release` no longer matches `CHANGELOG.md` (it loads with `VERSION`, when a release starts).
- After the change (observed in a later session, rules injected on each read): a shell script loads 4 rules (`naming`, `error-handling`, `cli`, `shell`; 11.2 KB, about 4.2k, −2.3k); `CHANGELOG.md` loads 3 (`changelog`, `versioning`, `docs`; 6.3 KB, about 2.3k, −1k). The rule sets are observed; the token figures are estimates (2.7 bytes per token), no `/context` delta was taken for these two reads.

### Second series: the four rules not yet triggered

Same method (fresh session, `/context all` before and after one `Read`, nothing else in between; a `/context` output itself adds about 0.8k to the next measure and is subtracted). Files that do not exist in this repository were created as untracked one-line fixtures and removed afterwards.

| File read | File | Rules loaded | Rule bytes | ~Tokens of rules |
|-----------|------|--------------|------------|------------------|
| `tests/test_skills.py` (11.5 KB) | tests | `testing`, `tdd`, `naming`, `error-handling`, `logging` | 16.1 KB | ~5.4k |
| `pyproject.toml` (0.7 KB) | manifest | `compatibility`, `dependencies` | 3.9 KB | ~1.35k |
| `openapi.yaml` (1 line) | API spec | `api` | 5.3 KB | ~1.8k |
| `src/api/users.py` (1 line) | API code | `naming`, `error-handling`, `logging` (`api` already loaded, **not reloaded**) | 10.1 KB | ~3.4k |

- The four triggers work as designed: `tests/**` and `**/test_*.py` load `testing` and `tdd`; manifests load `dependencies`; `**/openapi*.{yml,yaml,json}` and `**/api/**` load `api`.
- A rule is paid **once per session**, however many files or patterns match it.
- Scoped rules are counted under Messages in every case; Memory files stayed constant.
- On small files the rules cost more than the file: about 5.4k of rules for a 4k test file, about 1.8k for a one-line `openapi.yaml`. An API-flavoured Python project pays about 5.2k of rules.
- The first prompt of a session pays a one-time injection of about 26k in Messages (skill listing, deferred tool names, MCP instructions, `CLAUDE.md` content); it does not depend on the prompt and must be subtracted when attributing a cost.
- Two candidates for narrowing, not changed: `logging` (about 1k) matches every `**/*.py`, test files included, although it targets non-CLI applications; `compatibility` (about 1.1k) loads on `pyproject.toml` although its content is mostly shell, OS and XDG.

Rules without a natural file trigger (`tdd`, `release`, `versioning`, `dependencies`) depend on the files touched; a task that never opens a matching file never loads them. They are Phase 4 skill candidates, as planned.

## Findings that shaped the measurement

- A first run showed only 451 memory tokens: the core was **not loaded**. Claude Code resolves a relative `@import` against the real path of the symlinked `CLAUDE.md`, so `@core/…` looked in `agents/claude/core/`. Fixed in #41 (`@../../core/…`), confirmed by this run. The 451-token figure is not a valid "after" measurement.
- The same mechanism meant the `@rules/…` imports of 0.6.1 and 0.7.0 never resolved either: the `~/.claude/rules/` auto-load alone loaded the rules. The earlier "same real path" explanation was wrong; the baseline figures are unchanged (see the note in `baseline-0.6.1.md`).

## Reading

- The always-on cost fell from about 25k to 3.7k memory tokens, with the same normative content reachable through the core, the scoped rules and the skills (invariants test).
- The known cost of 0.7.0 (transition skills duplicating loaded rules) is gone: `review`, `pr`, `issues`, `quality` and `editor` live only in their skills.
