# ISO/IEC 25010 mapping

ISO/IEC 25010 (product quality model) groups software quality in nine characteristics. The names below are those of the 2023 edition (edition 2, published November 2023): Interaction capability replaces usability, Flexibility replaces portability, and Safety is new. This table maps each to the ai-rules dimensions, so that a project can check it has not forgotten one. The sub-characteristics are summarised; the standard is the reference.

| ISO/IEC 25010 characteristic | Sub-characteristics (summary) | ai-rules dimensions |
|------------------------------|-------------------------------|---------------------|
| Functional suitability | completeness, correctness, appropriateness | Correctness |
| Performance efficiency | time behaviour, resource use, capacity | Performance |
| Compatibility | co-existence, interoperability | Interoperability, Portability |
| Interaction capability (formerly usability) | learnability, operability, user error protection, inclusivity, user assistance, self-descriptiveness | User-friendliness, Accessibility |
| Reliability | faultlessness, availability, fault tolerance, recoverability | Reliability, Robustness, Resilience |
| Security | confidentiality, integrity, non-repudiation, accountability, authenticity, resistance | Security, Privacy & data minimisation, Auditability |
| Maintainability | modularity, reusability, analysability, modifiability, testability | Maintainability, Evolvability, Testability |
| Flexibility (formerly portability) | adaptability, scalability, installability, replaceability | Portability, Evolvability |
| Safety | operational constraint, risk identification, fail safe, hazard warning, safe integration | Safety |

**Additions beyond the standard:** Observability (understanding behaviour in production, supports reliability and analysability) and Privacy & data minimisation as its own dimension (the standard treats confidentiality as part of security; privacy by design and data protection law call for more).

## How to use it

1. At kickoff, walk the nine characteristics and mark each as critical, relevant or not applicable for this project.
2. For each critical one, name the dimension(s) from the right-hand column and read their guidance.
3. Record the choices and the conscious trade-offs (for example "performance over portability") in `README.md` or the design document.
4. Re-check the table when the scope changes (a CLI that gains a web interface now needs Accessibility; a tool that starts storing user data now needs Privacy).
